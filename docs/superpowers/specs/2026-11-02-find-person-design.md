# 이 사람 찾기 (동의한 주요 인물의 다른 조각 찾기) 설계

- 날짜: 2026-11-02
- 상태: 설계 승인 완료, 스펙 검토 대기
- 관련: `docs/superpowers/specs/2026-10-30-face-mosaic-studio-design.md` (R1 스펙 — 이 문서가 §2 "ReID/임베딩 금지" 조항을 개정한다), `docs/progress-log.md`

## 1. 목적과 범위

검수자가 **출연에 동의한 주요 인물 몇 명**(브이로거, 동행)만 모자이크를 풀고 나머지는 모두 가린 채 내보내려 할 때, 그 사람의 트랙이 수십 개 조각으로 흩어져 있어 하나씩 찾아 묶는 일이 오래 걸린다. 이 기능은 검수자가 고른 한 사람과 **비슷한 얼굴 조각을 영상 안에서 찾아 후보로 보여 주고**, 검수자가 확인한 조각만 그 사람에 묶는다.

**사용자가 정한 것**

| 항목 | 결정 |
|---|---|
| 주 용도 | 동의한 소수 주요 인물만 해제. 나머지는 계속 가림 |
| 방식 | "이 사람 찾기": 검수자가 먼저 고른 한 사람과만 비교 (행인끼리 묶는 처리 없음) |
| 확정 | 후보를 썸네일로 한 화면에 보여 주고, 틀린 조각을 빼고 묶음 단위로 추가. 해제는 별도 동작 |
| 저장 | 얼굴 특징 벡터는 저장하지 않음. 조각 ID와 유사도만 저장 |
| 실행 시점 | 검수자가 버튼을 눌렀을 때만 (분석 단계에서는 돌리지 않음) |

**범위 밖**: 영상 사이 인물 비교, 행인 자동 묶기, 자동 해제, 분석 단계 자동 실행, 얼굴 벡터 저장.

## 2. 안전·개인정보 원칙 (불변식)

1. 이 기능의 어떤 경로도 `edits.visible`에 확인 없이 조각을 추가하지 않는다. 노출은 지금처럼 `edits.visible`만으로 정해지며, 렌더와 미리보기는 `find_person.json`을 읽지 않는다.
2. 이미 보이는 사람에 조각을 추가할 때는 추가될 조각 썸네일을 다시 보여 주고 "추가하면 N개 조각이 보이게 됩니다"를 확인받는다.
3. 얼굴 특징 벡터, 정렬된 얼굴 이미지는 디스크·로그·Redis 어디에도 쓰지 않는다. 메모리에서만 쓰고 작업이 끝나면 버린다.
4. 기능 스위치 `FIND_PERSON_ENABLED`의 기본값은 꺼짐. 법무 승인 후 켠다. 꺼져 있으면 API는 404, 화면에는 버튼이 없다.
5. 같은 시간에 화면에 함께 나오는 조각은 같은 사람 후보가 될 수 없다.

## 3. 사용 흐름

```
오른쪽 목록에서 사람 선택 (동의자)
   └─ [이 사람 더 찾기]  ← 그 사람에게 큰 얼굴 조각(§4.2 조건)이 하나 이상 있을 때만 활성
        └─ 진행률 표시 (후보 i/N)
             └─ 후보 목록: 조각 썸네일 + 등장 시간, 유사도 순
                  · 유사도 ≥ CHECK_SCORE(초기 0.6): 체크된 상태
                  · SHOW_SCORE(초기 0.45) ≤ 유사도 < CHECK_SCORE: 체크 해제 상태
                  · SHOW_SCORE 미만: 표시 안 함
                  · [아님]: 후보에서 빼고 기록 (다시 찾아도 안 나옴)
             └─ [선택한 조각을 이 사람에 추가]
                  · 그 사람이 가림 상태 → 묶기만, 계속 가림
                  · 그 사람이 보임 상태 → 추가될 조각 썸네일 재표시 + 확인 → 묶고 보임 유지
```

- 후보가 없으면 "찾을 수 있는 후보가 없습니다 (얼굴 60px 이상, 15프레임 이상 조각 기준)"를 보여 준다.
- `truncated`이면 "시간 제한으로 일부 후보만 확인했습니다"를 함께 보여 준다.
- 진행 중 다른 편집(분할 등)을 하면 결과를 받을 때 §5.4 규칙으로 무효 처리한다.

## 4. 워커

### 4.1 큐와 처리기

- 새 큐 `queue:find`. 기존 워커 루프는 메시지를 하나씩 처리하므로(`worker/mosaic_worker/main.py` `run_once`), 몇 분 걸릴 수 있는 찾기가 수동 박스 추적·렌더를 막지 않도록 **이 큐만 처리하는 별도 처리기**를 둔다.
  - `python -m mosaic_worker.main --queues find` 형태로 큐를 지정해 실행할 수 있게 하고, 기존 처리기는 `find`를 소비하지 않는다.
  - `docker-compose.yml`에 같은 이미지의 `worker-find` 서비스를 추가한다.
- 상태는 Redis 해시 `find:{jobId}` (`state: queued|running|done|failed`, `progress`, `error`, `updatedAt`), 만료 6시간.

### 4.2 입력과 후보

- 요청 메시지: `{jobId, personKey, pieceIds}` — 찾을 사람을 이루는 조각 ID 목록(분할 반영: `t2a`, `t2b` 같은 조각 ID).
- 조각은 `edits.json`의 분할을 반영해 `compose.split_fragments`로 만든다. 렌더와 같은 함수라 조각 경계가 일치한다.
- 후보 조건 (모두 만족):
  - 찾는 사람의 조각이 아님
  - 조각 얼굴 크기 중앙값 ≥ `MIN_FACE_PX`(60, 25% 확장 전 크기 기준), 실제 검출 프레임 ≥ `MIN_DETS`(15)
  - `suspect`가 아님
  - 찾는 사람의 어느 조각과도 시간이 겹치지 않음
  - 등장 시간이 긴 순으로 최대 `MAX_CANDIDATES`(300)개

### 4.3 얼굴 특징과 비교

- 조각마다 점수 상위 40프레임에서 고르게 최대 5프레임을 고른다. 찾는 사람은 조각들을 합쳐 최대 10프레임.
- 고른 프레임을 **프레임 순서로 정렬해 한 번에 순방향으로 읽는다**(임의 이동 최소화).
- 각 프레임에서 YuNet을 다시 돌려 박스와 IoU ≥ 0.5인 검출의 5점으로 `FaceRecognizerSF.alignCrop` → `feature` → L2 정규화.
- 조각의 5프레임 중 2개 이상에서 얼굴을 못 찾으면 후보에서 뺀다(귀·손·자막 같은 비얼굴 제거).
- 조각 벡터 = 프레임 벡터 평균의 정규화. 유사도 = 찾는 사람 벡터와의 코사인.
- 시간 제한 `TIME_CAP_SEC`(120). 넘으면 그때까지 계산한 후보로 끝내고 `truncated: true`.

### 4.4 결과 파일 `find_person.json` (작업 폴더)

```json
{
  "version": 1,
  "state": "done",
  "personKey": "g1",
  "pieceIds": ["t3", "t17a"],
  "tracksVersion": "<tracks.json의 sha256 앞 16자>",
  "splits": [{"trackId": "t2", "frame": 1200}],
  "params": {"showScore": 0.45, "checkScore": 0.6, "minFacePx": 60, "minDets": 15,
             "model": "face_recognition_sface_2021dec.onnx", "modelSha256": "0ba9fbfa…"},
  "truncated": false,
  "candidates": [{"pieceId": "t42", "score": 0.71}, {"pieceId": "t88b", "score": 0.52}],
  "dismissed": ["t90"]
}
```

- `candidates`에는 `SHOW_SCORE` 이상만, 유사도는 소수 둘째 자리로 반올림해 저장한다.
- 같은 작업에서 새로 찾으면 파일을 교체한다. 단 이전 결과의 `pieceIds`가 새 `pieceIds`에 모두 들어 있으면(같은 사람이 조각을 더 얻은 경우) `dismissed`를 이어받는다. 묶을 때마다 그룹 ID가 바뀌므로 `personKey`로는 비교하지 않는다.
- 쓰기 직전에 작업 폴더가 있는지 다시 확인하고, 없으면 쓰지 않는다(지워진 작업 폴더를 되살리지 않음).
- 실패 시 `state: failed`, `error`에 사용자용 문구(모델 없음, 영상 읽기 실패 등).

### 4.5 모델

- `worker/scripts/fetch_model.sh`에 `face_recognition_sface_2021dec.onnx`를 추가하고 SHA-256(`0ba9fbfa01b5270c96627c4ef784da859931e02f04419c829e83484087c34e79`)을 확인한다. YuNet에도 같은 체크섬 확인을 추가한다.
- 출처: OpenCV zoo, Apache 2.0. 학습 데이터는 공식 페이지에 명시가 없어 법무 검토 목록에 포함한다.

## 5. API

### 5.1 엔드포인트

| 메서드 | 경로 | 동작 |
|---|---|---|
| `POST` | `/jobs/:id/find-person` | `{personKey, pieceIds}` 검증 후 큐에 넣음. 이미 `queued/running`이면 409 |
| `GET` | `/jobs/:id/find-person` | Redis 상태 + `find_person.json` 결과 |
| `PUT` | `/jobs/:id/find-person/dismissed` | `{pieceIds}`를 `dismissed`에 반영 |

- 모두 기존 작업 소유권 검사를 거친다. `FIND_PERSON_ENABLED`가 꺼져 있으면 404.
- `POST`마다 감사 로그 한 줄: 사용자, 작업 ID, 시각. 결과는 남기지 않는다.

### 5.2 작업 삭제

- `removeJob`에서 `find:{id}` 키를 지운다. 같은 김에 이미 남고 있는 `manual:{id}:*` 키도 지운다.

### 5.3 그룹 이름 검증 수정 (선행 작업)

- 현재 `apps/api/src/jobs/edits.validator.ts`는 그룹에 `label` 문자열을 필수로 요구하지만, `groupPersons`(`apps/web/src/lib/edits.ts`)는 이름 없는 그룹을 만들고 `Studio.tsx`가 그대로 저장한다. 코드상 이름 없는 두 사람을 묶으면 저장이 거부된다(실행 확인 전).
- 수정: `label`을 선택 항목으로 바꾸고(있으면 문자열·200자 이하), 이름 없는 그룹 저장 e2e 테스트를 추가한다. 이 기능의 "추가"가 `groupPersons`를 쓰므로 먼저 고친다.

### 5.4 결과 무효화

- API는 `GET` 응답에 `stale`을 넣는다. 결과의 `tracksVersion`이 현재 `tracks.json`의 해시와 다르거나, 결과의 `splits`가 현재 `edits.json`의 분할과 다르면 `true`. 화면은 `stale`이면 "편집이 바뀌어 다시 찾아야 합니다"를 보여 주고 후보를 쓰지 않는다.

## 6. 웹

- 오른쪽 상세(`TargetDetail`)에 [이 사람 더 찾기] 버튼, 결과 카드(후보 썸네일 격자, 체크박스, [아님], [선택한 조각을 이 사람에 추가]).
- 후보 중 이미 **다른 사람의 그룹**에 들어 있는 조각은 보여 주지 않는다(검수자가 이미 다른 사람으로 정한 조각). 대상 사람에 이미 들어 있는 조각도 마찬가지다.
- 썸네일은 기존 트랙 썸네일을 쓴다. 분할된 조각은 그 조각 구간의 샘플이 있으면 그것을, 없으면 트랙 썸네일에 "분할된 조각" 표시.
- 추가 동작:
  - 대상 사람과 후보 조각들을 `groupPersons`로 묶는다. `groupPersons`는 묶는 사람 중 하나라도 가림이면 결과를 가림으로 만든다.
  - 대상이 보임 상태였으면 확인 대화상자를 거친 뒤 `setPersonVisible(묶인 사람, true)`를 호출한다. 확인을 취소하면 묶지 않는다.
  - 되돌리기 이력에는 묶기(와 보임 변경)만 들어간다. [아님]은 서버 파일에만 기록한다.
- 기능 스위치는 `GET /jobs/:id/find-person`의 404 여부로 판단해 버튼을 숨긴다.

## 7. 스펙 개정

R1 스펙 §2의 "ReID/임베딩 금지(생체정보 회피 전제)"를 다음으로 바꾼다.

> 얼굴 인식은 검수자가 작업마다 명시적으로 요청한 "이 사람 찾기"에서만 쓰며, 기능 스위치(기본 꺼짐)로 제어한다. 얼굴 특징 벡터는 메모리에서만 쓰고 저장하지 않으며, 결과는 조각 ID와 유사도만 남긴다. 법무 승인 전에는 켜지 않는다.

## 8. 검증

### 8.1 동작 고정 테스트

- 워커
  - 찾는 사람과 시간이 겹치는 조각은 후보가 되지 않는다.
  - `suspect`, 크기·검출 수 미달 조각은 후보가 아니다. 5프레임 중 2개 이상 얼굴 재검출 실패 조각도 아니다.
  - 후보가 0개면 `state: done`, `candidates: []`.
  - 결과 JSON에 길이 2 이상의 실수 배열이나 `embedding`/`feature` 키가 없다(스키마 테스트).
  - 시간 제한을 넘으면 부분 결과와 `truncated: true`.
  - 작업 폴더가 지워진 뒤에는 파일을 만들지 않는다.
  - 분할이 있으면 조각 단위(`t2a`, `t2b`)로 후보를 낸다.
- API (e2e)
  - 스위치가 꺼져 있으면 세 엔드포인트 모두 404.
  - 다른 사용자의 작업에 404, 실행 중 재요청 409.
  - 이름 없는 그룹 저장이 통과한다.
  - 작업 삭제 시 `find:{id}`와 `manual:{id}:*` 키가 지워진다.
- 웹
  - 가림 상태 사람에 추가하면 `visible`이 늘지 않는다(속성 테스트: 추가 전후 보이는 조각 집합이 같거나 줄어듦).
  - 보임 상태 사람에 추가하면 확인 전에는 아무것도 바뀌지 않고, 확인을 취소하면 편집이 그대로다.
  - 버전이 다른 결과는 후보를 쓰지 않는다.
- 렌더
  - `find_person.json`이 있어도 `contracts/fixtures/expected-mask-frames.json`과 같은 마스크가 나온다.

### 8.2 출시 전 측정 (기능 스위치를 켜기 전 조건)

- 영상 3종: Pexels 학생 영상(`test-media/pexels-students-10clips-1080p.mp4`), 파리 거리 브이로그, 한국인 얼굴이 나오는 짧은 자체 촬영본.
- 영상마다 후보 조각에 사람 라벨을 붙이고, 주요 인물별로 찾기를 실행해 잰다.
  - 기본 체크 후보 중 다른 사람 수 (목표 0)
  - 표시 후보 중 다른 사람·비얼굴 비율
  - 그 사람의 실제 조각 중 후보로 나온 비율(재현율)
  - 실행 시간, 후보 수, `truncated` 여부
- `CHECK_SCORE`는 기본 체크 후보에 다른 사람이 0건이 되는 가장 낮은 값으로, `SHOW_SCORE`는 재현율과 오류 비율을 보고 정한다. 결과는 `docs/progress-log.md`에 남긴다.

## 9. 위험과 남는 한계

| 위험 | 대응 |
|---|---|
| 다른 사람이 체크된 채 추가되고, 이후 해제로 노출 | 기본 체크 기준을 측정으로 정함, 보임 상태 추가 시 재확인, 썸네일 전체 표시 |
| 분할한 트랙의 다른 사람 조각이 함께 묶임 | 조각 단위 후보·추가, 분할이 바뀌면 결과 무효 |
